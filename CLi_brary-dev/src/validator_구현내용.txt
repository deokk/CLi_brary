validator.py 구현 내용 정리
================================

작성자: 김민재
최종 수정: 2026-04-10


1. 개요
-------
validator.py는 프로그램 실행 시 data/ 폴더 내 4개 데이터 파일의
무결성을 검사하는 모듈이다. 기획서 5절에 명시된 환경 검사, 문법 규칙,
의미 규칙을 기준으로 구현했다.


2. 경로 설정
-----------
src/validator.py 기준으로 상위 디렉토리를 프로젝트 루트로 잡고,
루트/data/ 경로에서 4개 파일을 참조한다.

  - _USERS_FILE    = data/users.txt
  - _BOOKS_FILE    = data/books.txt
  - _RENTALS_FILE  = data/rentals.txt
  - _SYSTIME_FILE  = data/system_time.txt


3. 공개 API (clibrary.py에서 호출)
----------------------------------
  - check_environment()       : 프로그램 시작 시 전체 환경 검사 수행
  - validate_date(date_str)   : 날짜 존재 여부 검사 (4.1.1)
  - validate_date_format_only(date_str) : YYYY-MM-DD 형식만 검사
  - validate_date_not_past(date_str)    : 시간 비가역성 검사 (5.4.2)
  - get_saved_system_time_str()         : 저장된 날짜 문자열 반환
  - save_system_time(date_str)          : system_time.txt에 날짜 저장
  - has_violations()           : 위반 항목 존재 여부
  - get_cached_violations()    : 위반 항목 목록 반환
  - delete_violation(index)    : 특정 위반 항목 삭제
  - delete_all_violations()    : 전체 위반 항목 삭제


4. 환경 검사 흐름 (check_environment)
-------------------------------------
기획서 5.1.3 ~ 5.4.2 순서를 따름.

(1) 홈 경로(프로젝트 루트) 존재 확인
    - 실패 시 오류 출력 후 sys.exit(1)

(2) data/ 폴더 확인, 없으면 생성 시도

(3) system_time.txt 확인
    - 없으면 오류 출력 후 종료 (기획서 5.4.2)

(4) users.txt / books.txt / rentals.txt 확인
    - 없으면 경고 출력 후 빈 파일 생성 시도 (기획서 5.1.3, 5.2.3, 5.3.3)
    - 생성 실패 시 오류 출력 후 종료

(5) 각 파일의 읽기/쓰기 권한 확인
    - 권한 없으면 오류 출력 후 종료

(6) 문법 규칙 검사 + 의미 규칙 검사 수행
    - 위반 항목을 _cached_violations 리스트에 저장
    - 위반이 있으면 "문법 위배 항목이 발견되었습니다." 출력


5. 파일별 레코드 형식
---------------------

[users.txt] 4필드
  <ID>/<비밀번호>/<권한>/<대출정지_종료일>

  기획서 5.1.1 본문에는 3필드로 기재되어 있으나
  6.2.2에서 "관리자 여부 필드(0/1)"를 명시하고 있어서
  권한 필드를 포함한 4필드로 구현함.
  이 부분은 기획서 내부 모순에 해당하므로 수정판에 반영 예정.

[books.txt] 5필드
  <도서번호>/<카테고리>/<제목>/<저자>/<현재상태>

[rentals.txt] 6필드
  <대여번호>/<ID>/<도서번호>/<대여일>/<반납기한>/<실제반납일>

  기획서 4.4절 구성과 5.3.1에 연장횟수 필드가 정의되어 있지 않아
  6필드로 구현함.

[system_time.txt] 1줄
  YYYY-MM-DD 형식 날짜 1개만 존재


6. 문법 규칙 검사 (check_syntax_rule)
-------------------------------------

[system_time.txt]
  - 비어있지 않은 행이 정확히 1줄이어야 함
  - YYYY-MM-DD 형식이고 실제 존재하는 날짜여야 함
  - 2000년 이후만 허용

[users.txt]
  - 슬래시(/)로 나눴을 때 정확히 4필드
  - ID: 9자리 숫자 또는 "admin" (기획서 4.2.1)
  - 비밀번호: 8~16자, 숫자/알파벳/!@# 만 허용,
    각 최소 1개 포함, 동일 문자 3회 이상 연속 금지 (기획서 4.2.2)
  - 권한: "0" 또는 "1" (기획서 6.2.2)
  - 대출정지 종료일: "NONE" 또는 유효한 YYYY-MM-DD (기획서 4.2.3)

[books.txt]
  - 슬래시(/)로 나눴을 때 정확히 5필드
  - 도서번호: C333-22 형식, C는 [FSHTAPLG] (기획서 4.3.1)
  - 카테고리: 8개 허용 문자열 중 하나 (기획서 4.3.2)
  - 도서번호 첫 글자와 카테고리 첫 글자 일치 확인 (기획서 4.3.2)
  - 제목: 최대 32자, 숫자/알파벳/한글/공백만, 앞뒤 공백 불가 (기획서 4.3.3)
  - 저자: 최대 32자, 숫자/알파벳/한글/()/공백만, 앞뒤 공백 불가 (기획서 4.3.4)
  - 현재상태: "RENTED" 또는 "AVAILABLE" (기획서 4.3.5)

[rentals.txt]
  - 슬래시(/)로 나눴을 때 정확히 6필드
  - 대여번호: R + 4자리 숫자 (기획서 4.4.1)
  - ID: 9자리 숫자 (admin 제외, 기획서 4.4.2)
  - 도서번호: C333-22 형식 (기획서 4.4.3)
  - 대여일: 유효한 YYYY-MM-DD (기획서 4.4.4)
  - 반납기한: 유효한 YYYY-MM-DD (기획서 4.4.5)
  - 실제반납일: "NONE" 또는 유효한 YYYY-MM-DD (기획서 4.4.6)


7. 의미 규칙 검사 (check_semantic_rule)
---------------------------------------

[users.txt] (기획서 5.1.2)
  - 같은 ID가 두 개 이상 존재하면 안 됨

[books.txt] (기획서 5.2.2)
  - 같은 도서번호가 두 개 이상 존재하면 안 됨

[rentals.txt] (기획서 5.3.2)
  - 대여번호 중복 불가
  - 도서번호가 books.txt에 존재해야 함
  - ID가 users.txt에 존재해야 함


8. 위반 항목 관리
-----------------
위반 항목은 ViolationItem 데이터클래스로 관리한다.
  - filename: 파일명 (예: "users.txt")
  - line_number: 줄 번호 (1-based)
  - line_content: 해당 줄 원문

검사 결과는 모듈 레벨 _cached_violations 리스트에 저장되고,
violations 명령어에서 조회/삭제할 수 있도록
delete_violation(), delete_all_violations() 함수를 제공한다.


9. 내부 유틸리티 함수
---------------------
  - _parse_date(s): YYYY-MM-DD 파싱, 2000년 이후만 허용
  - _read_lines(filepath): UTF-8로 파일 읽기
  - _is_valid_password(pw): 비밀번호 문법 검증
  - _is_valid_book_id(book_id): 도서번호 형식 검증
  - _is_valid_rental_id(rental_id): 대여번호 형식 검증
  - _parse_user_ids(): users.txt에서 ID 집합 추출
  - _parse_book_ids(): books.txt에서 도서번호 집합 추출


10. 참고사항
-----------
  - 기획서 5.1.1의 3필드 vs 6.2.2의 권한 필드 모순은
    기획서 수정판에서 4필드로 통일할 예정
  - 기획서에 연장횟수 데이터 요소가 정의되어 있지 않아
    rentals.txt는 6필드로 구현함
  - 정규표현식은 Python 표준 re 모듈(fullmatch) 사용
